# โครงสร้างข้อมูลของเว็บ (lazy load)

ตั้งแต่ 26 ก.ค. 2569 หน้าเว็บไม่โหลด `clusters-data.js` (3.6 MB) ตอนเปิดหน้าอีกแล้ว
ข้อมูลถูกแยกเป็น 2 ระดับตามว่า "ต้องใช้เมื่อไหร่"

| ไฟล์ | โหลดเมื่อไหร่ | ขนาด (หลังบีบอัด) | เนื้อหา |
|---|---|---|---|
| `clusters-core.js` | พร้อมหน้าเว็บ | ~100 KB | hull, สถิติรายกลุ่ม, ขอบแผ่นเปลือกโลก, จุดภาพรวมโลก 14,615 จุด |
| `pts/<slug>.json` | เมื่อผู้ใช้เลือกประเทศ | 1–166 KB ต่อไฟล์ | จุดครบความละเอียดของประเทศนั้น |
| `clusters-data.js` | **ไม่โหลด** | — | ข้อมูลต้นทาง เก็บไว้สำหรับสร้างไฟล์ข้างบนใหม่ |

ผลลัพธ์: หน้าแรกโหลด 900 KB → 100 KB (ลด 89%) และหน่วยความจำ 51 MB → 19 MB

## เมื่ออัปเดตข้อมูลแผ่นดินไหว

หลังแก้ `clusters-data.js` แล้ว **ต้องรันคำสั่งนี้ทุกครั้ง** มิฉะนั้นเว็บจะยังแสดงข้อมูลเดิม:

```bash
node build-data.js clusters-data.js .
```

สคริปต์จะเขียนทับ `clusters-core.js` และไฟล์ทั้งหมดใน `pts/` แล้วสรุปขนาดที่ได้ให้ดู

## ข้อควรรู้

- **ต้องเปิดผ่านเว็บเซิร์ฟเวอร์ (http/https)** — เปิดไฟล์ `index.html` จากดิสก์โดยตรง (`file://`)
  เบราว์เซอร์จะบล็อก `fetch` ทำให้เลือกประเทศไม่ได้ หน้าเว็บจะขึ้นข้อความแจ้งเตือน
  ถ้าจะทดสอบในเครื่อง ให้รัน `python3 -m http.server` ในโฟลเดอร์นี้
- จุดภาพรวมโลกลดความละเอียดด้วยการแบ่งกริด 0.35° แล้วเก็บจุดที่แมกนิจูดสูงสุดในแต่ละช่อง
  ปรับค่าได้ที่ตัวแปร `GRID` ใน `build-data.js` (เล็กลง = ละเอียดขึ้น ไฟล์ใหญ่ขึ้น)
- ตอนเจาะดูรายประเทศ ข้อมูลที่แสดงเป็นจุดครบทุกจุดเหมือนเดิม ไม่มีการลดความละเอียด
- ไฟล์ที่โหลดแล้วถูกแคชไว้ในหน่วยความจำ เลือกประเทศเดิมซ้ำจะไม่โหลดใหม่
